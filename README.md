# 🧠 LLM Notes

Проект для экспериментов с промптингом LLM: два провайдера — локальный и облачный — реализованы через общий конструктор классов (`ABC`). Промптинг в связке с векторной БД **Chroma**: поиск по смыслу (по вектору/эмбеддингу), а не по ключевым словам.

## 🎯 Цель проекта

Промптинг с разными LLM-провайдерами и семантический поиск по эмбеддингам.

## ✅ Что реализовано

- Два LLM-провайдера (локальный + облачный) за общим интерфейсом через `ABC` / `abstractmethod`
- Промптинг и генерация ответов через оба провайдера
- Векторная БД Chroma (асинхронный клиент) — хранение эмбеддингов и поиск по смыслу
- Базовый RAG: найденный по вектору контекст подставляется в промпт

```python
from abc import ABC, abstractmethod

class BaseLLM(ABC):
    @abstractmethod
    async def generate(self, prompt: str) -> str:
        ...

class OllamaLLM(BaseLLM): ...
class MistralLLM(BaseLLM): ...
```

## 🛠 Стек и инструменты

Python 3.11+ (async, ООП) · ChromaDB (async-клиент) · Ollama · Mistral AI · Эмбеддинги · RAG · NumPy · Docker

## 💡 Выводы

LLM-провайдер скрыт за абстракцией (`ABC`) — вызывающему коду неважно, отвечает локальная модель или облачная. Основной фокус проекта — связка «эмбеддинг → векторный поиск → контекст → промпт», а не промпт-инжиниринг сам по себе.
